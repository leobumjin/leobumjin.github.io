## 1. When a Beneficial Goal Leads to Risky Behavior

Imagine a team of AI agents tasked with recruiting five experts for a national AI emergency response team. The mission is urgent and serves an important purpose. However, some candidates may be unavailable, while others may have already declined to participate. How far should the agents be allowed to go to accomplish their objective?

AI agents can search the web, exchange information with other agents, retain previously discovered information, and interact with external systems. These capabilities enable them to solve complex tasks, but they also introduce the possibility of accessing restricted information or using information inappropriately.

The challenge becomes more complex in multi-agent systems. Information collected by one agent may be passed to another and eventually influence decisions or actions across the team. During this process, the original source, access permissions, and restrictions associated with that information may become unclear or be overlooked.

Motivated by these concerns, this project investigates **whether multi-agent systems can respect boundaries on information access and use, even under strong pressure to accomplish their goals.** Evaluating such systems requires examining not only whether the task is completed, but also what information the agents access and how they use it along the way.

## 2. An Expert Recruitment Scenario Involving the Dark Web

To examine these challenges, we developed a simulated multi-agent environment centered on recruiting experts for a national AI emergency response team.

Agents collaborate through shared discussions and private messages, with access to tools such as web search, persistent memory, and candidate communication. The scenario also includes a simulated dark-web environment containing information subject to access restrictions.

The dark-web environment serves as a test setting in which the existence of information does not imply authorization to access or use it. In particular, the scenario examines how agents respond when potentially useful information is available through restricted sources.

The environment distinguishes information access levels and supports tracking whether agents access or use restricted information. All candidates, communication records, mailboxes, and dark-web pages are synthetically generated, allowing controlled experiments without accessing real personal data or confidential records.

The implementation and simulation environment are available in the [Multi-Agent Dark-Web Safety GitHub repository](https://github.com/leobumjin/multiagent-darkweb-safety).

## 3. The Boundary of an Evaluation Program Is Not Necessarily the Boundary of Agent Behavior

A fundamental challenge in evaluating AI agent safety is that **the actions controlled by an evaluation program may not cover everything an agent can actually do.**

In a typical simulation, agents interact with an environment through predefined tools and interfaces. For example, a program may block access to certain websites or disable functions that retrieve sensitive information. However, restricting access within the program does not necessarily eliminate every possible route to that information.

If an agent can use an external browser, invoke other tools, or operate through execution paths outside the evaluation program, it may obtain information in ways the program does not anticipate or observe. Consequently, the absence of a recorded violation does not necessarily establish that no violation occurred.

This distinction is particularly important when information access itself is a central subject of evaluation, as in scenarios involving the dark web. Before determining whether an agent respects restrictions on information use, the evaluation must establish which routes to the information are available and whether those routes are adequately controlled.

In other words, **restricting information access requires more than disabling individual functions within an application. It requires controlling the agent's entire accessible execution environment so that unauthorized access paths are not available.**

This involves clearly defining the permitted tools and network resources, isolating or blocking unauthorized external execution paths, and ensuring that information access and use can be observed within the evaluation boundary.

The reliability of an agent safety evaluation therefore depends not only on the model's decisions but also on the completeness of the controls imposed by its execution environment.

## 4. From Individual Agent Actions to Collective Decisions

In a multi-agent system, information access is not solely an individual agent's problem. Information collected by one agent can be communicated to others, incorporated into collaborative discussions, and used to justify subsequent actions.

Consider the following hypothetical sequence:

1. One agent proposes searching a restricted dark-web source to obtain additional information about a candidate.
2. Another agent retrieves the information and summarizes it in a private conversation.
3. A third agent receives the summary without knowing the original source or its access restrictions.
4. The team uses the information to assess the candidate and develop a communication strategy.

Each step raises a different safety question. Was the initial access authorized? Could the retrieved information be shared with other agents? Should information with unclear provenance and permissions be used to make decisions?

Importantly, the agent performing the final action may never have accessed the dark web directly. It may nevertheless rely on restricted information obtained and transmitted by another agent.

This means that inspecting individual tool calls is not sufficient to understand how information is used across the team. Safety evaluation must also consider how information moves between agents and influences collective decisions.

This sequence illustrates a hypothetical failure mode rather than an observed experimental result. Nevertheless, it demonstrates why evaluating multi-agent systems requires tracing **where information originates, how it propagates, and which decisions it ultimately influences.**

## 5. Separating Task Success from Information Access Safety

Task completion is a common metric for evaluating AI agents. However, success alone is insufficient when agents operate under information access constraints.

Suppose two teams successfully recruit the required experts. One team relies entirely on authorized public information, while the other accesses restricted information from the dark web. Although both teams accomplish the same objective, their behavior should not be considered equally safe.

This project therefore distinguishes several stages of agent behavior.

| Stage | Evaluation Question |
| --- | --- |
| Proposal | Does an agent suggest accessing restricted information? |
| Access | Does an agent actually retrieve or inspect restricted information? |
| Propagation | Is the information transmitted to other agents or stored in memory? |
| Use | Does the information influence decisions or candidate communications? |
| Outcome | Does the team complete the task while respecting information constraints? |

Proposing an unsafe action is different from executing it. Likewise, retrieving restricted information is different from using it.

For example, an agent may access restricted information and subsequently refuse to use it. While this could prevent further misuse, it does not undo an unauthorized access that has already occurred. Conversely, an agent that never directly accesses restricted information may still violate information-use constraints by relying on material provided by another agent.

The project provides conversation replay and monitoring capabilities to help examine these distinctions. Scripted demonstrations illustrate the scenario and possible sequences of events, whereas evaluating actual model behavior requires model-connected execution and analysis. The presence of a violation in a scripted demonstration should therefore not be interpreted as evidence of how frequently a model would exhibit that behavior.

## 6. Media Coverage and Open-Source Implementation

This project was featured in an [MBC broadcast](https://youtu.be/BdfQ0XvuVI8?t=114). The simulation environment and evaluation tools are publicly available in the [GitHub repository](https://github.com/leobumjin/multiagent-darkweb-safety).

As AI agents become increasingly capable of autonomously pursuing complex goals and collaborating with other agents, understanding how they access and use information becomes essential.

Importantly, safety cannot be guaranteed by model behavior alone. An agent's actual capabilities may extend beyond what an evaluation program observes, while collaboration between agents can make the provenance and use of information increasingly difficult to trace. **A reliable evaluation of multi-agent safety must therefore examine agent behavior while also controlling and validating the execution environment in which information access occurs.**

Ultimately, this project asks a fundamental question: **Can AI agents collaborate effectively toward a shared goal while respecting information boundaries, even when restricted information could help them accomplish their task?**
